# plan: 生体情報の取扱い方針 (保存範囲・保持・削除・同意・アクセス制御・復旧)

Memoria #1048 完了条件「顔写真・生体情報の保存範囲、保持期間、削除、同意、アクセス制御を仕様化」
「誤認識・なりすまし・端末紛失時の復旧および人手確認フロー」の正本。

> **2026-09-12 方針変更**: 顔テンプレートと顔写真の正本を Cernere から **Ostiarius ローカル**へ移し、
> 生体情報を施設外へ出さない。経緯・代替・移行は [face-data-local-only.md](face-data-local-only.md)。
> 以下の表はその方針で改訂済み。Cernere 正本時代の記述は同ファイル §1 の「変更前」を参照。

## 1. 保存範囲 (何を持ち、何を持たないか)

| データ | Ostiarius | Cernere | Aedilis | 備考 |
|---|---|---|---|---|
| 照合 / enroll の動画フレーム | **持たない** (メモリ処理のみ、ログ・ディスク書き込み禁止) | **持たない** | 持たない | ショットは抽出後に破棄 |
| プロフィール顔写真 (1 枚) | **正本** (AES-256-GCM 封緘、鍵はホスト内のみ) | **持たない** | 持たない | §1.1。表示用途と登録の種を兼ねる。施設外へ出さない |
| 顔テンプレート (512d) | **正本** (施設単位、AES-GCM 封緘、鍵はホスト内のみ) | **持たない** | 持たない | 施設間配布はしない。逆変換リスクを暗号化 + 鍵分離で下げる |
| ランドマーク / blendshapes | 持たない (判定後破棄) | — | — | チャレンジ判定の一時値 |
| 生体性スコア / 一致スコア | 監査ログに数値のみ (失敗行は user 無し) | — | 要約のみ (件数) | |
| パスキー公開鍵 | キャッシュ | 正本 | — | 既存 |
| 同意記録 | 写し (照合可否の判定用) | 正本 (policyVersion, at, facility) | — | |
| 失効指示 | 受領して執行 | 正本 (userId, facilityId, reason, at。30 日保持) | — | 生体情報を含まない |
| 出席記録 | 持たない | — | 正本 | attestation 経由 |
| 氏名フル | 持たない (弱識別 hint のみ) | 正本 | 既存通り | kiosk 画面に出さない |

### 1.1 プロフィール顔写真を保存する (2026-08-18 方針変更、2026-09-12 に保存先を Ostiarius へ)

**変更前は顔写真を一切保存しなかった。** 職員が名簿・出席確認画面で本人の顔を見られるように
するため、neco 判断でプロフィール顔写真 1 枚に限り保存を認める。

変えたこと / 変えないこと:

- **保存するのはプロフィール顔写真 1 枚だけ。** 照合フレーム・enroll のショットは従来どおり
  メモリ処理のみで破棄する。「写真を保存する」を全フレームへ広げない。
- 正本は **Ostiarius** (2026-09-12 変更。それ以前は Cernere)。テンプレートと同じ AES-256-GCM で
  封緘し、鍵 ID を分ける。Cernere と GLab は**保存しない** — 職員画面の表示は施設 LAN 内で
  Ostiarius から都度取得し、応答は `Cache-Control: private, no-store`。**施設外からは見えない。**
- 写真のアップロード先は **kiosk /enroll (LAN 内)**。GLab プロフィールからのアップロード経路は廃止
  (写真が Cernere を経由しないようにするため)。
- **照合には写真を使わない。** 写真から抽出したテンプレートは `pending` 状態で保管し、
  職員が実機で本人確認して `active` へ昇格させたものだけが出席照合に載る
  ([../feature/face-photo-seeded-enrollment.md](../feature/face-photo-seeded-enrollment.md))。
- **kiosk 待機画面には出さない。** 氏名フルを kiosk に出さないのと同じ理由 (来場者に他人の
  個人情報を晒さない)。表示先は職員の名簿・出席確認画面 (LAN 内) と、kiosk 上での本人確認時に限る。

引き受けたリスク (承知の上で保存する):

- 写真は**テンプレートより復元容易な個人情報**であり、漏洩時の被害が大きい。暗号化・
  アクセス制御・監査で下げるが、ゼロにはならない。
- 写真が存在すること自体が **提示攻撃 (§6「なりすまし報告 (写真提示等)」) の材料**になる。
  そのため写真を照合経路へ入れず、`active` 昇格に職員立会いを必須にしている。
- kiosk ホストの物理侵害で当該施設の写真・テンプレートが晒される。Cernere 侵害で全施設が
  晒される旧構成より範囲は狭いが、ホストのディスク暗号化と鍵の別媒体保管が前提になる。

## 2. 保持期間

| データ | 期間 | 削除トリガ |
|---|---|---|
| テンプレート (Ostiarius 正本) | 在籍中、同意から 365 日で再同意 | Cernere からの失効指示 (卒業/退会/所属離脱、撤回、再同意なし)、職員無効化、Ostiarius 自前の 365 日超過判定 |
| プロフィール顔写真 (Ostiarius 正本) | テンプレートと同じ | テンプレートと**同一トリガで同時削除** |
| 同意の写し (Ostiarius) | テンプレートと同じ | 同上 |
| 失効指示 (Cernere) | 30 日 | 期限。Ostiarius の復元時に先に適用する |
| 施設内バックアップ | 直近 7 世代 | ローテート |
| 監査ログ (Ostiarius) | 90 日 | 日次ローテート |
| outbox | 送信成功まで、最大 7 日 | 送信成功 / 期限 |
| kiosk セッション状態 | 60 秒 | TTL |

## 3. 削除

- 生徒本人: Cernere プロフィール「顔認証の登録を削除」→ Cernere が**失効指示**を積む (生体情報は
  Cernere に無いので削除するものは同意の `revokedAt` だけ)。Ostiarius は次回 sync (最長 15 分) で
  pull して物理削除。kiosk 上での「今すぐ反映」は職員の即時 sync。
- kiosk 上での本人による削除 (職員立会い) も可。この場合 Ostiarius が即時削除し、Cernere へ
  同意撤回を打つ。
- **写真とテンプレートは常に同時に消す。** 「顔認証の登録を削除」は写真・`pending`/`active`
  テンプレート・同意の写しの全てを対象にする。写真だけ残る / テンプレートだけ残る状態を作らない
  (片方が残ると、削除したつもりの個人情報が名簿に出続ける)。
- 職員: 誤登録・なりすまし疑い時に kiosk で無効化 (理由必須、Ostiarius 監査ログ + Cernere audit へ要約)。
- 削除後の再登録は enroll をやり直す (旧テンプレートは復元しない)。
- バックアップ復元時は Cernere の失効指示 30 日分を先に適用してから照合を再開する。

## 4. 同意

- 抽出前に **必ず** 同意画面 (目的・保存するもの/しないもの・保存先・保持期間・撤回方法・問い合わせ先) を表示し、
  生徒本人がタップ。同意文は Cernere が version 管理し、変更時は再同意。
- **写真を保存する旨と表示範囲を同意文に明記する** (誰が見るか = 職員の名簿・出席確認画面 (施設内) と本人。
  kiosk 待機画面には出さないこと)。
- **保存先が施設の kiosk 端末のみで、施設外 (クラウド) へ出さないことを同意文に明記する。**
  2026-09-12 の方針変更に伴い `policyVersion` を上げ、既存の同意者には再同意を求める。
  旧 policyVersion の同意だけを持つ生徒のテンプレート・写真は Cernere 撤去時に削除し、再 enroll を求める。
- 写真の提出に同意しない生徒も、**職員立会いの enroll (写真なし) で顔認証を使える**。
  写真必須にすると、同意しない生徒から顔認証経路を丸ごと奪うことになる。
- 未成年 (高校生等) を含む施設は保護者同意の運用を施設側で行い、`consent.policyVersion` に
  施設ポリシー ID を含める (システムは記録のみ、判定は施設運用)。
- 顔認証そのものに同意しない生徒は **パスキー経路のみ**で出席できる (不利益を最小化)。
  プロフィール写真の保存だけに同意しない生徒には、上記の職員立会い enroll (写真なし) も残す。

## 5. アクセス制御

- kiosk / enroll 画面: `OSTIARIUS_KIOSK_TOKEN` (端末に設定) + 職員操作は職員 passkey。
- 失効指示・同意の pull: Cernere service token に scope `face-revocation:read` / `face-consent:read` + facility 制限。
  生体情報はこの経路に乗らない。
- 写真取得: Ostiarius `GET /identity/face-photo/:userId` は **LAN 内 + 職員セッション必須**。
  取得は 1 件ずつで、一覧一括ダウンロードの口を作らない。閲覧は誰がどの生徒の写真を見たかを
  Ostiarius 監査ログに残す。施設外 (Cloudflare Tunnel 等) へこの経路を公開しない。
- Ostiarius DB: テンプレート列・写真列は暗号化。鍵は **kiosk ホスト内で生成し、ホスト外へ出さない**
  (TPM 封緘 → OS 資格情報ストア → 0600 鍵ファイル + ディスク暗号化、の優先順)。Infisical に置かない。
- sidecar: localhost のみ。管理 API (`/identity/admin/*`) は職員セッション必須。
- ログ: 画像・テンプレート・氏名を出力しない lint (`test/no-biometric-log.test.ts` で文字列検査)。
  写真バイト列・data URL・base64 画像も同じ lint の対象にする。
- バックアップ媒体と鍵媒体は分離する (同じ USB に置かない)。

## 6. 復旧・人手確認フロー

| 事象 | 一次対応 | 二次対応 | 記録 |
|---|---|---|---|
| 誤拒否 (本人なのに no_match/ambiguous) | やり直し 3 回 → パスキー経路 | 職員 override → 後日再登録 | `no_match` 件数を施設別に週次で見る |
| 誤受理の疑い (別人で issued) | 職員が Aedilis 出席を取消 + Ostiarius で該当テンプレート無効化 | 両者を職員立会いで再登録、閾値見直し | `verification_events` + Aedilis 側 |
| なりすまし報告 (写真提示等) | 当該 attestation を Aedilis で無効化 | チャレンジ必須化 (`OSTIARIUS_FACE_CHALLENGE=required`)、物理監督 | 監査ログ + Cernere audit |
| 他人の写真で登録申請 | `pending` のまま昇格しない (職員が実機で不一致を確認) | 当該 user の写真を削除 + 職員が事情確認 | Ostiarius 監査ログ (昇格却下の理由) + Cernere audit へ要約 |
| 端末紛失 (パスキー) | 生徒/職員が Cernere で失効 → 即時 sync | 新端末で device-link 再登録 | Cernere audit |
| カメラ/sidecar 故障 | kiosk は自動で `fallback` (パスキー QR) | 職員 override (`camera_down`) | health + override 理由 |
| Cernere 不通 | 顔照合は正本がローカルなので継続、パスキーは直近 sync キャッシュで継続 | enroll は同意記録が打てないため不可、device-link も不可 (要 Cernere) | sync 失敗 warn |
| kiosk ホスト故障 / ディスク喪失 | パスキー経路 + 職員 override で出席継続 | 施設内バックアップから復元 (失効指示を先に適用)。無ければ全員再 enroll | 復元記録 |
| Aedilis 不通 | outbox に積んで再送 | 7 日超で職員に通知 | outbox 件数 |

## 7. 未決事項
- 保護者同意の記録を Cernere に持たせるか (現状: 施設ポリシー ID のみ)。
- テンプレートの施設間共有: **しない**と決定 (2026-09-12)。別施設では再 enroll。
- TPM の無いホスト (Raspberry Pi 系) での鍵保護 (鍵ファイル + ディスク暗号化で妥協するか)。
